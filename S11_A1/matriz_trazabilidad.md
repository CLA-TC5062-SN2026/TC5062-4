# Matriz de trazabilidad del proyecto DAFI

## 1. Propósito

Esta matriz relaciona cada requerimiento funcional del SRS de equipo v3.0 con sus criterios de aceptación, historias del backlog, contrato OpenAPI, código backend y frontend, y evidencia de prueba localizada. La especificación o el esquema de datos no se toman como prueba de implementación: una ruta OpenAPI, tabla SQL, maqueta o captura por sí sola no acredita un flujo funcional. Los estados describen la cobertura observable en el commit auditado, no una promesa de trabajo futuro.

## 3. Criterios de clasificación

- **Completo:** la totalidad de los criterios esenciales del RF están implementados de extremo a extremo y hay evidencia verificable. Si no hay prueba automatizada, se requiere una prueba manual documentada que cubra los criterios esenciales.
- **Parcialmente implementado:** existe una parte funcional en código, pero faltan criterios, integración frontend/backend, UI funcional, seguridad, automatización o reglas importantes. Una API parcial no completa el flujo de usuario.
- **No implementado:** solo hay especificación, diseño, esquema, maqueta o fixtures, o no se encontró una implementación funcional del comportamiento requerido.
- **No aplica:** solo si el RF se retiró formalmente o fue reemplazado por una decisión documentada. No se encontró tal retiro para ningún RF.

La columna de pruebas distingue pruebas automatizadas (incluidas colecciones Newman, cuando existe output), evidencia de ejecución manual documentada, evidencia visual y ausencia de evidencia. Un archivo de test o una afirmación de documentación sin output asociado no se presenta como ejecución exitosa.

## 6. Cobertura por área

- **Identidad y autenticación:** el backend implementa registro, login JWT y consulta de sesión. Verificación de correo, recuperación, bloqueo por intentos e invalidación remota de sesión no están implementados.
- **Familias y perfiles:** el backend implementa operaciones CRUD de perfiles con controles de rol/propiedad parciales. El ciclo de cocuidador, invitaciones y consentimiento de adulto no está integrado de extremo a extremo.
- **Conversaciones:** existen operaciones backend para crear, listar, editar y enviar borradores, además de consultas de mensajes/eventos. La captura de respuestas, carga segura de fotos, solicitud de información, indicaciones y cierre no cubren la totalidad de criterios.
- **Mensajes y eventos:** existen operaciones base; el conjunto de tipos de evento y transiciones del SRS no está completo.
- **Notificaciones y administración:** no existe módulo funcional de entrega de notificaciones, avisos temporizados, reportes o desactivación de cuentas.
- **Catálogos:** las rutas de etiquetas y avisos exponen datos; no implementan por sí mismas la captura de respuestas ni el aviso persistente en las pantallas.
- **Frontend:** login y listado de perfiles tienen integración real documentada. Las vistas de nueva conversación, hilo, bandeja e historial consumen `datos-demo.ts` en partes importantes y son prototipos visuales, no recorridos completos contra el backend.
- **Operaciones no construidas o incompletas:** correo, procesos programados, resumen/modelo, carga segura de fotos, administración de reportes, eliminación/retención integral y despliegue público.

## 7. Brechas prioritarias

1. **Identidad, consentimiento y círculo médico (impacto/riesgo muy alto; costo cualitativo alto):** se implementaron registro/login y algunas verificaciones de autorización, pero faltan verificación de correo, consentimientos completos, invitaciones y gestión de permisos compartidos. Estos límites restringen quién puede participar y qué información puede enviarse.
2. **Flujo de conversación de extremo a extremo (impacto/riesgo muy alto; costo alto):** el backend cubre parte de creación y envío; no se completa la secuencia de respuestas, fotos seguras, solicitud de información, indicaciones, notificaciones y cierre, ni su integración en UI.
3. **Resumen de contexto (impacto alto; riesgo alto; costo alto):** OpenAPI define citas verificables y filtradas por permisos, pero no se encontró módulo de resumen, integración de modelo, fallback ni evaluación implementados.
4. **Privacidad y operaciones (impacto alto; riesgo alto; costo medio/alto):** el borrado de perfil no cubre el ciclo de datos de conversaciones/fotos/cuenta; no se encontraron auditoría completa, política operativa de retención, correo ni administración de reportes.
5. **Integración de interfaz (impacto alto; riesgo medio; costo medio):** las pantallas principales de conversación, historial y bandeja usan fixtures; el login y el listado de perfiles son las integraciones reales documentadas.
6. **Pruebas representativas (impacto medio/alto; riesgo medio; costo medio):** los outputs cubren solicitudes y escenarios seleccionados, no la totalidad de los AC. No hay evidencia automatizada para fotos, consentimiento, resumen, notificaciones y varios flujos no implementados.
